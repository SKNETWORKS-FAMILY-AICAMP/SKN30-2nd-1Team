# Designer Skill (튜브어때 — UI / UX)

## Objective

광고주가 **5초 이내**에 채널 위험도와 추천 결과를 직관적으로 이해할 수 있는 **Streamlit 기반 대시보드**를 설계·구현한다.
모든 렌더링은 Business Logic 계층이 제공한 **예측 결과 객체/CSV**와 DBA 계층이 제공한 **정제 데이터셋**을 소비만 하며, 데이터 가공·모델 호출은 본 계층의 책임이 아니다.

디자인 계층의 핵심 책임은 다음 세 가지다:

1. 채널 검색 → 분석 결과 → 추천으로 이어지는 사용자 플로우를 매끄럽게 제공한다 ([docs/튜브어때_PRD.md](../../../docs/튜브어때_PRD.md) §13).
2. 위험도 점수·등급·SHAP 위험 원인을 광고주가 즉시 해석할 수 있는 시각화로 표현한다.
3. 데이터 기준일·한계점·면책 문구를 사용자에게 명확히 노출한다 (PRD §19, §20).

## Scope

### 포함 (In Scope)

- **Streamlit 대시보드 구성** (PRD §13)
  - 메인(검색) / 분석 결과 / 추천 화면 구조
  - 사이드바, 페이지 전환, 세션 상태 관리
- **시각화 컴포넌트** (PRD §13-2)
  - 위험도 게이지 (Plotly)
  - SHAP 위험 원인 막대그래프
  - 업로드/조회수 시계열 차트
  - 추천 채널 카드 리스트 및 위험도 비교 뷰
- **사용자 입력 UX**
  - 채널 URL / 채널 ID 입력창
  - 입력 형식 가이드, 인기 카테고리 빠른 검색
  - "분석 불가" 케이스의 친절한 안내 메시지
- **메시지·면책 표기**
  - "2026-05-17 기준 데이터로 분석되었습니다" 같은 스냅샷 기준일 안내 (PRD §6-1)
  - PRD §20 윤리 고지 노출
- **반응성·접근성**
  - 로딩 스피너, 빈 상태(empty state), 에러 상태 처리
  - 색상·대비, 한글 폰트 가독성

### 제외 (Out of Scope — 다른 계층에 위임)

- **데이터 수집/스키마 정의** → DBA 계층 ([dba/SKILL.md](../dba/SKILL.md))
- **모델 학습·추론·SHAP 계산** → Business Logic 계층 ([business-logic/SKILL.md](../business-logic/SKILL.md))
  - 본 계층은 산출된 SHAP 값을 **표시**만 하고, 직접 계산하지 않는다.
- **Feature 계산식·이탈 정의·threshold 튜닝** → Business Logic 계층
- **CSV 직접 가공·정렬·조인** → DBA / Business Logic 계층이 사전에 제공한 결과만 사용

## Key Responsibilities

1. **PRD §13 화면 구조 충실 구현**
   - 메인 → 분석 결과 → 추천의 3단 플로우를 유지한다.
   - 각 화면에서 다음 요소를 반드시 노출한다:
     - 메인: 채널명/URL 입력창, 인기 카테고리 빠른 검색
     - 분석 결과: 위험도 게이지, 위험 원인 막대그래프, 업로드/조회수 시계열 차트, **데이터 기준일**
     - 추천: 추천 채널 카드 리스트, 채널별 위험도 비교

2. **위험도 등급의 시각적 일관성**
   - A (안전) / B (주의) / C (위험) 색상·라벨링을 전체 화면에서 통일한다.
   - 색상만으로 정보를 전달하지 않도록 라벨/아이콘을 병행한다 (접근성).

3. **5초 이내 응답 KPI 지원** (PRD §22)
   - 무거운 계산을 화면 렌더링 시점에 트리거하지 않는다. 사전 계산된 `predictions_YYYYMMDD.csv`를 lookup하는 방식으로 구성한다.
   - Streamlit `@st.cache_data` / `@st.cache_resource`를 적극 활용한다.

4. **사용자가 분석 불가 케이스를 이해할 수 있게 안내** (PRD §6-1, §19)
   - CSV에 없는 채널을 입력한 경우: "이 채널은 2026-05-17 기준 사전 수집 데이터에 포함되지 않아 분석할 수 없습니다" 같은 명시적 메시지 노출.
   - 임의의 더미 결과를 보여주지 않는다.

5. **면책·윤리 문구 노출** (PRD §20)
   - "본 결과는 통계적 추정치이며 광고 의사결정의 참고용입니다" 같은 문구를 분석 결과 화면 하단에 고정.

6. **반응형·빈 상태·에러 상태 처리**
   - 로딩 중에는 스피너 / 스켈레톤 사용.
   - 검색 전, 결과 없음, 오류 발생 등 각 상태별 UI를 명확히 분리.

## Constraints & Guidelines

### 계층 경계 (Boundary Rules)

- **모델 호출·재학습 금지**: UI 코드에서 `XGBoost.fit()`, SHAP explainer 생성 등을 직접 호출하지 않는다. Business Logic 계층이 제공한 함수/결과만 사용한다.
- **CSV 스키마 변경 금지**: 시각화에 더 편한 형태가 필요하더라도 `data/processed/*.csv` 컬럼을 임의로 추가·변경하지 않는다. 필요하면 DBA / Business Logic 계층에 변경 요청.
- **비즈니스 규칙 결정 금지**: 등급 컷오프(예: A/B/C threshold), 위험도 가중치, 추천 정렬 기준은 본 계층에서 정의하지 않는다. 이미 정의된 규칙을 **표시**만 한다.
- **데이터 수집 코드 호출 금지**: 화면 렌더링 중 YouTube API를 직접 호출하지 않는다. MVP는 스냅샷 기반이다 (PRD §6-1).

### UX 원칙

- **명료성 우선**: 광고주가 마케팅 의사결정을 내릴 수 있도록 핵심 숫자(위험도, 등급, Top-3 원인)를 한 화면에 노출.
- **데이터 기준일 항상 표시**: 모든 분석 화면 상단/하단에 스냅샷 기준일을 표기한다.
- **색상 의존 금지**: 색맹 사용자를 고려해 라벨/아이콘을 병행한다.
- **한국어 우선**: 라벨, 안내, 에러 메시지는 한국어로 제공한다 (PRD가 한국 광고주 대상).

- Streamlit 앱 코드: [app/](../../../app/)
- 시각화 유틸: `app/` 하위 또는 `src/visualization/` (Business Logic 산출물을 받아 그리는 어댑터 역할)
- 정적 자산(로고, 이미지): [docs/](../../../docs/) 또는 `app/assets/`
