# 채널 단위 Feature 설계 계획 — all_channels + all_videos → 1채널 1행

## Context

**문제 설정**: YouTube 크리에이터의 **이탈(`is_churned`)** 을 예측하는 ML 모델의 입력 데이터를 만든다. 모델은 채널 단위로 동작하므로 입력은 **채널 1개 = 1행** 이어야 한다.

**입력 자원**:
- [`data/raw/channels/csv/all_channels.csv`](../data/raw/channels/csv/all_channels.csv) — 채널 1개 = 1행 (8,108행)
- [`data/raw/videos/csv/all_videos.csv`](../data/raw/videos/csv/all_videos.csv) — 영상 1개 = 1행 (376,979행). 채널당 최근 ~50개
- [`data/raw/youtube_channels_cleaned.csv`](../data/raw/youtube_channels_cleaned.csv) — `is_churned` 라벨 + `category` 보유

**기준 카탈로그**: 팀 표준 (`docs/유튜브_피처목록_초안.pdf` 의 A~E 5개 카테고리). 본 문서는 그 카탈로그를 **현재 raw 데이터로 무엇을 만들 수 있고 무엇은 불가능한지** 매핑하고 계산식을 명세한다.

## 0. 확정된 설계 결정

| # | 결정 사항 | 함의 |
|---|---|---|
| 1 | **`is_churned` 정의 = 마지막 영상 후 180일(6개월) 이상** | "최근 활동" 관련 피처는 라벨 누설. 별도 격리 필요. |
| 2 | **추세 기준점 = 채널별 마지막 영상 시점 (anchor=last_video)** | 모든 채널에서 "활동 종료 직전 패턴" 을 동일하게 비교. "오늘 기준" 윈도우는 사용 안 함. |
| 3 | **영상 < 10개 채널 = 학습에서 제외** | 표준편차·추세 피처가 의미 없는 채널은 행 자체 제거. |
| 4 | **`category` 문자열은 정제 단계에서 그대로 보존** (인코딩 X) | one-hot/target encoding 은 모델 학습 시 train/val 분리 후 수행. |
| 5 | **로그 변환은 정제 단계에서 미리** (`log_subscriber_count` 등 컬럼 추가) | 원본과 로그값 둘 다 저장. EDA 편함. |

## 1. 라벨 누설 경고 — `is_churned = 180일 룰` 기준

라벨 정의가 시점 기반이므로, **"오늘 - 마지막 영상" 또는 그와 강하게 연관된 통계는 라벨을 그대로 알려주는 셈**. 이런 피처는 학습에서 제외하거나 별도 격리.

### 🚫 학습 피처에서 제외 (직접 누설)

| 피처 | 이유 |
|---|---|
| `days_since_last_video` | 오늘 - 마지막 영상. 180일 초과 = 라벨 1 → 라벨 그 자체 |
| `last_video_at` | 위와 동일 정보. 시점 그대로 |
| (오늘 기준) `최근 3개월 영상 수` | 라벨이 1이면 정의상 0 |
| (오늘 기준) `최근 3개월 조회수` | 라벨이 1이면 정의상 NaN/0 |

→ **메타용으로만 보존** (`last_video_at` 은 디버깅·EDA 용도. 모델 입력에서는 drop).

### ⚠️ 주의해서 계산하면 사용 가능 (간접 누설 가능성)

| 피처 | 안전한 계산법 |
|---|---|
| `max_gap_days` | **수집된 영상 사이의 최대 공백만**. `(today - last_video)` 포함 금지 |
| `hiatus_count_30d`, `hiatus_count_90d` | 위와 동일. 영상-영상 간격만 카운트 |
| `std_upload_interval_days` | 영상-영상 간격만 |
| `recent vs prev` 시리즈 | **anchor = 채널별 마지막 영상**. "오늘" 기준 윈도우는 절대 사용 금지 |

### ✅ 안전 (라벨 정의와 무관)

규모(B의 구독자/조회수 절댓값), 평균 영상 길이, Shorts 비율, 참여율(like_rate, engagement_rate), 채널 나이 등 시점에 의존하지 않는 통계.

## 6. 추세 피처 계산 규칙 (anchor=last_video)

결정 #2 에 따라 **모든 "최근 vs 이전" 피처는 채널별 마지막 영상 시점을 0으로 두고 거꾸로 계산**.

**방식**: 영상 인덱스 기반 ("최근 10개 vs 이전 10개"). 시간 기반보다 구현 단순하고 영상 ≥ 10개 채널만 사용하므로 NaN 없음.

```python
# 의사 코드 — 채널별로 영상을 published_at 내림차순 정렬
videos_sorted = df_vi.sort_values(["channel_id", "published_at"], ascending=[True, False])

# 최근 10개 vs 이전 10개 (총 20개 이상 영상 채널만)
recent = videos_sorted.groupby("channel_id").head(10)
prev   = videos_sorted.groupby("channel_id").nth(slice(10, 20))

view_change_rate = recent.avg_views / prev.avg_views
```

영상 10~19개 채널은 추세 피처만 NaN. 영상 < 10개 채널은 결정 #3 에 따라 행 제거.

- **단변량 ROC-AUC** — 한 피처만으로 이탈을 얼마나 가르는지. **0.85+ 면 누설 의심 → 해당 피처 재검토**. ⚠️ 9개 피처 우선 검사
- 상관계수 매트릭스 (다중공선성)
- `category` 별 이탈률 (인코딩 전략 결정용)
- 최종 행 수 / NaN 분포 / 라벨 균형 확인

## 8. MVP → 풀버전 단계적 확장

| 단계 | 포함 피처 | 개수 | 목적 |
|---|---|---|---|
| **MVP** | A (⚠️ 제외) + B (⚠️ 제외, log 포함) | ~22 | 베이스라인 ROC-AUC 측정 |
| **+C** | + C 구독자 반응 (반응 안정성) | ~28 | 참여 신호 추가 |
| **+E 안전** | + E 의 std/cv (⚠️ 제외) | ~31 | 안정성 신호 |
| **+추세 ⚠️** | + ⚠️ 9개 (anchor=last_video) | ~40 | 마지막 영상 직전 패턴. **점수가 급등하면 누설 의심** |
| **+ 부가** | + `views_per_sub` 류 보강 | ~45 | 비율 피처 |
| **+ D** | (선택) 광고 — **재수집 필요** | +6 | 광고 패턴 |
| **+ C 텍스트** | (선택) KoBERT — **DL팀** | +3 | 댓글 감성 |
| **+ E 외부** | (선택) Google Trends | +1 | 외부 검색량 |
